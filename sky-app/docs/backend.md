# SkyGuide Backend Build Plan

Backend: Supabase (Postgres + Auth + Edge Functions), free tier, no card required.
Frontend stays as-is (Vite + React + TS) — no framework migration.
Weather data: Open-Meteo (no key, no card, 10K free daily calls, non-commercial use).

## Day 1 notes

- `src/lib/supabaseClient.ts` — single shared Supabase client, reads `VITE_SUPABASE_URL` /
  `VITE_SUPABASE_ANON_KEY` from env, throws early if they're missing.
- `.env.example` — template for the two env vars. Copy to `.env.local` and fill in real
  values from Supabase Project Settings → API. `.env.local` is already gitignored (`*.local`).
- No schema yet — that's Day 2. Today is just "the app can talk to Supabase."

### How to verify Day 1 locally

```sh
npm install
cp .env.example .env.local   # then fill in your real Supabase URL + anon key
npm run dev
```

Nothing in the UI changes yet — this just confirms the client initializes without throwing
the "Missing Supabase env vars" error in the console.

## Day 6 notes — weather API decision

Using [Open-Meteo](https://open-meteo.com/): no API key, no sign-up, no credit card,
10,000 free daily calls for non-commercial use. Only needs `latitude`/`longitude`, which
each destination already has. Requires a CC BY 4.0 attribution credit somewhere on the site.

Example request the Edge Function will make per destination:

```
https://api.open-meteo.com/v1/forecast?latitude=36.39&longitude=25.46&current=temperature_2m,relative_humidity_2m,wind_speed_10m
```
